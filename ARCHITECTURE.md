# Personal Lastfind architecture

The personal application in `apps/selfhost` composes the shared source in `packages/core`. Vinext renders React/shadcn in a native Cloudflare Worker that also owns API routes and scheduled monitoring. Shared code has one source; application-specific owner authentication is composed at the edition boundary.

Control D1 holds the owner, project registry, canonical prompt configuration, durable jobs, leases and temporary publication outbox. Every project owns an isolated SQLite Durable Object containing normalized answers, cited and consulted evidence and report indexes. Original provider responses are stored separately in a private R2 bucket with checksums and ownership metadata.

The generated owner key authenticates the personal instance. Sessions bind the configured origin and key. All data routes enforce ownership; missing required storage fails closed. The installer provisions required resources and validates R2 availability before changes, without activating paid infrastructure subscriptions.

`/app` requires owner authentication and renders persisted projects, prompts and collected reports. Workspace/project routes and filters have canonical URLs, and new projects start with no collected answers. The storage and API contracts below remain available.

A native five-minute scheduled handler collects each project daily or weekly, on the day and hour chosen in its settings, in the workspace's time zone (by default Monday 04:00; America/Sao_Paulo when none is stored). Durable reservations, leases and conservative budget holds prevent duplicate submissions after uncertain provider outcomes. Providers with standard endpoints use normal-priority batch; Live-only endpoints retain their actual behavior. Results are archived, normalized, staged through a temporary outbox and published idempotently into project SQLite. The browser never starts monitoring on page refresh.

AI apps (Claude, ChatGPT, Cursor and other MCP clients) connect to `POST <origin>/mcp`. They sign in through OAuth 2.1 on the owner consent screen (`/app/connect`, PKCE, discovery under `/.well-known/`) or use a personal access token created in Settings > AI apps. Only token hashes are stored; tokens expire, can be revoked at once and are limited to 60 calls a minute. Read tools return the same reports as the app; write tools (prompts, topics, brand decisions) need the write permission, are marked for client confirmation and are audited. No read starts a paid provider call.

The Agent runs in the same Worker: one OpenRouter chat model reads the project's reports through the same tools the AI apps use, writes artifacts whose data blocks are computed from project data and validated before saving, and keeps the project's Brain (files and a Memory) and the owner's skills, each with a version history that can be restored. A background curator reads finished or rated conversations and records what was taught; a skill is learned only from the same kind of work done well in several conversations, and a change learned after a turn read third-party content waits for approval. Every model call is reserved before it is sent and settled at its reported cost.

Every paid reservation (collection, evaluations, Semantic Branding, the Agent and its learning) is one guarded statement that must fit the project's monthly budget (US$ 50 by default for a new project, none for one created before budgets existed), the optional installation brake (US$ a month, US$ a day, collections a day; none by default) and the collection caps `SELF_HOST_MONTHLY_LIMIT` and `GLOBAL_DAILY_RUN_LIMIT`. A refused reservation records why, and the project's screens say it. The owner sets the budget in Settings > Monitoring > Budget and the brake in Admin > Usage and costs; Admin also holds the provider keys (sealed under `CREDENTIALS_KEY`) and the model of each classifier.

Reports query bounded server-side views; response bodies, source details and history load on demand. Private authenticated APIs are not cached publicly. Export streams bounded pages. Backup/restore validates identity, row counts and checksums in an isolated generation before switching; raw R2 objects require their own backup. Project backups also carry the owner's Agent conversations as a copy for the record; a restore checks and skips them.

`npm run setup` guides configuration and initial deployment. `npm run deploy:selfhost` publishes subsequent updates. Each development worktree has isolated generated runtime and local Wrangler state. Keep secrets and generated configuration outside version control.
