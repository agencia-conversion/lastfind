# Lastfind shell design (the logged-in app)

Scope: `/app` in both editions and the public `/demo`. That is everything rendered by `LiveAnalyticsApp`, plus dialogs, sheets and menus.
Reference screens: **Overview** and **Brands**. When this file is silent, copy what those two screens do. When a screen disagrees with this file, the screen is wrong.
This is the one source of the app's visual rules: `packages/core/DESIGN_SYSTEM.md` only maps the code and the URL contract, and the site, docs and 404 follow [site.md](site.md). Keep this file updated in the same PR that changes a token, a catalog component or a rule. The guard `tests/design-docs.test.mjs` fails when a token in `tokens.css` is missing here.

## 1. Principles
1. **One way to do each thing.** Before writing a component, search `packages/core/components/ui`, `components/lastfind/presentation` and `components/analytics/shared.tsx`, using the table in section 12.
   - If something close exists, extend it with a `cva` variant and show the variant in `/design-system`.
   - A second implementation is a bug, even if it looks the same.
2. **Tokens only.** Colour, size, weight, radius, height and spacing come from `packages/core/app/tokens.css`.
   - No hex, no `[Npx]` and no Tailwind size or weight classes (`text-xs|sm|base|lg`, `font-normal|medium|semibold|bold`) outside `components/ui`.
3. **The smallest readable size, three weights.** Body text is 14px at 400 (regular), the chrome that is acted on 500, titles and metrics 600; nothing is smaller than 12px.
4. **The final layout appears from the first frame.** A skeleton is the real component in its `loading` state. A screen never jumps from one skeleton to another.
5. **Selection is shown by fill and colour, never by a border or ring.** Focus rings show only for the keyboard.
6. **English and pt-BR, 390px and 1280px+, light and dark.** No `·`, `•`, `|` or ` — ` used as a separator (a line break, a comma, a label or a column instead; guard `tests/no-middot.test.mjs`). A missing value is a dash with its reason in a `Hint`, never 0.
7. **No provider names.** What a customer reads never names the infrastructure behind it (search data, the AI service, hosting, email, the bot check): an outage says "The AI service is unavailable right now.", never the supplier or its status. Only Admin and the independent edition's keys and install guide name them. Guard: `tests/no-provider-name.test.mjs`.

## 2. Type

| Class (TSX) / var (CSS) | Size / line | Weight | Use |
|---|---|---|---|
| `text-caption` / `--text-caption` | 12 / 16 | `--weight-text` (400) | header meta, group labels (a menu's too), legends, axis labels, footnotes, badges in captions, a stacked card's labels |
| `text-menu` / `--text-menu` | 13 / 20 | `--weight-label` (500) | every menu's text: dropdown, select, combobox and command items, popovers, the calendar and the date presets (section 6) |
| `text-body` / `--text-body` | 14 / 21 | `--weight-text` (400) | every other text: running text, table cells and headers (every cell's text at this one size, its badges, codes and second lines too), nav rows, buttons, tabs, inputs, breadcrumbs, header-bar titles |
| `text-section` / `--text-section` | 16 / 24 | `--weight-strong` (600) | card titles (`SectionHeader`), dialog, sheet and alert titles |
| `text-title` / `--text-title` | 24 / 32, `--tracking-title` | `--weight-strong` (600) | the one in-content page title (`PageHeading`) |
| `text-metric` / `--text-metric` | 24 / 32, `tabular-nums`, `--tracking-title` | `--weight-strong` (600) | the `MetricCard` value |

Weights (`tokens.css`):
```css
--weight-text: 400;    /* what is read: running text, cells, inputs, captions, nav rows */
--weight-label: 500;   /* chrome that is acted on: menus, buttons, tabs, triggers, table headers, the active nav row */
--weight-strong: 600;  /* text-section, text-title, text-metric */
--tracking-title: -0.02em; /* text-title and text-metric (the page title had it alone) */
```
- **Three weights** (13/11/2026, for readability, after Tremor's Planner: regular text, medium controls, semibold headings). What is read is 400, what is acted on is 500, the three 600 roles above and an artifact's headings (document scale, below) are 600. `b` and `strong` take `--weight-label` and inherit inside table cells. No other weight exists; a screen changes weight only through these tokens.
- **Menus.** `[data-slot=dropdown-menu-content]`, `[data-slot=select-content]` and `[data-slot=popover-content]` set `font-weight: var(--weight-label)` themselves, so a portaled menu matches the sidebar. Every menu reads at one size, `text-menu` (13px: a step above the caption, below the 14px trigger that opens it), set once in `ui/dropdown-menu.tsx`, `ui/select.tsx`, `ui/combobox.tsx`, `ui/command.tsx`, `ui/popover.tsx` (a popover's text), `ui/calendar.tsx` (the days and the month; the weekdays are the caption) and in the date range's presets and popover (`.date-range-preset`, `.date-range-popover`): every menu, popover and calendar of the header and the app is the same size. A menu's group labels and shortcuts stay `text-caption`; the controls inside a popover (inputs, buttons) keep the control's size; their triggers stay `text-body`. Guard: `tests/shell-menus.test.mjs`.
- **Numbers.** `tabular-nums`. The family is Plus Jakarta Sans Variable.
- **Prose width.** `max-width: 72ch` (agent answers, notes, descriptions).
- **Document scale (artifacts and contents).** An artifact's text reads as a document, a step above the app, in Notion's scale (12/11/2026; Notion's page title 40px at line height 1.2, headings 1.875em, 1.5em and 1.25em of a 16px text at line height 1.3, the text at 1.5): text `--text-doc-body` 16 / 24; the document's title, the `h1` that opens it, `--text-doc-title` 40 / 48; any later `h1` `--text-doc-h1` 30 / 39, `h2` `--text-doc-h2` 24 / 31, `h3` `--text-doc-h3` 20 / 26, `h4` `--text-doc-h4` 18 / 24, all headings `--weight-strong`. More room above a heading than below it, as Notion (h1 32px, h2 24px, h3 16px, h4 12px above; 16px under the title, 12px under h1 and h2, 8px under h3 and h4), and the text centred at the width the person picks in the artifact's More menu, Width (Notion's way; this browser, per artifact; not on phones, where it fills the screen): Narrow `--doc-width` (about 70 characters a line), Standard `--doc-width-standard` (the default, an A4 or letter sheet), Wide `--doc-width-wide` (1024 px), Full (the whole pane). The shared link reads at Standard. Data blocks and Markdown tables keep the app's sizes. The reader (`AgentMarkdown document`: the read-only artifact, the public demo, the shared link) and the editor draw headings as headings with the same rules (`agent.css`); a chat answer's Markdown headings stay bold lines. Guard: `tests/artifact-document.test.mjs`.
- **Exceptions.** Inputs are `text-section` under 768px (no iOS zoom). The radar SVG keeps `--radar-unit`.

## 3. Heights and spacing tokens (`tokens.css` `:root`)
```css
--header-height: 48px;          /* every top bar */
--header-height-touch: 52px;    /* under 768px */
--control-height: 32px;         /* every button, input, select, trigger, tab: everywhere in the app */
--control-height-touch: 40px;   /* under 768px and (pointer: coarse) */
--nav-row-height: 32px;         /* every nav row; touch: --control-height-touch */
--nav-subrow-height: 28px;      /* a nested row of the main sidebar (Agent > Chat); touch: --control-height-touch */
--table-row-height: 42px;       /* existing */
--content-gutter: 28px;         /* existing; 20px under 1200px */
--content-max-width: 1700px;    /* existing */
--sidebar-width-app: 224px;     /* existing */
--tracking-label: 0.04em;       /* uppercase group labels */
```
- **Grid.** Every padding, margin and gap is a multiple of 4px, apart from 1px hairlines and 2px focus offsets. Values in use: 4, 8, 12, 16, 20, 24, 28, 32.
- **Content.** `.analytics-content` uses `padding: 24px var(--content-gutter) 24px`. `PageHeading` has `margin-bottom: 24px`, and its description has `margin-top: 4px` in `text-body text-muted-foreground`.
- **Card row.** Gap 20px, and 20px between rows.
- **The content's width, not the window's.** The content (`.live-content`) is a query container (`app-content`), and its layout breakpoints are container queries: the KPI strip in pairs at 880px or less (so five labels never wrap), side-by-side cards stacked at 970px or less, a single KPI column and stacked columns at 636px or less, phone tables at 720px or less (the old window breakpoints minus the sidebar and gutters). So a screen with Ask Lastfind docked lays out as on a tablet. Each container query sits after the window's media query it mirrors, which stays for the site's preview of the app (it has no content container); the window's min-width rules are scoped to that preview. Checked by `tooling/qa-pr/ask-panel-flow.mjs` (docked, 1280 and 1440: no sideways scroll, one-line KPI labels, no figure or name cut).

## 4. Header bar (one standard)
It applies to the app top bar (`.analytics-topbar`), `DetailHeader`, the mobile bar, the chat panel header and the chat bar (Agent > Chat, a `DetailHeader`). No other header exists.

- **Box.** `min-height: var(--header-height)`, `padding: 0 var(--content-gutter)`, one row, `gap: 8px`, `border-bottom: 1px solid var(--border)`, `background: var(--background)`. The hairline is inside the height: every bar is exactly `--header-height` (`DetailHeader`'s row is the token minus 1px), so two bars side by side end on the same line.
- **Left side.**
  - Order: `SidebarTrigger` (`size="icon"`, 32px), a 1x16px divider in `--border`, then the breadcrumb or title.
  - The path is `ui/breadcrumb` (`Breadcrumb`, `BreadcrumbList`, `BreadcrumbItem`, `BreadcrumbSeparator`, `BreadcrumbPage`). It starts at the screen, never at the project (the sidebar's switcher names it): "Brands", "Settings > Brand and market", "Agent > Contents", "Responses > the prompt".
  - The path has priority over the filters: it takes its own width (up to 24rem, a longer item truncates), the filters stay on one row. The filters that do not fit fold into the Filters button at the row's end (as on a phone), never clipped at the edge; it opens them all on the lines under the bar (`filtersThatFit`, `lib/filter-fit.ts`). While a filter's menu is open the row keeps its fold, so the menu stays under its trigger; it fits again when the menu closes. From 768 to 1599px, on a screen with filters, the path shows only the screen's or item's name (the sidebar marks the section), except a section's page, whose name alone is ambiguous: "Shopping > Overview", "Shopping > Brands", "Shopping > Products", "Traffic > AI Traffic".
  - Earlier crumbs are links where they lead somewhere, `text-body`, `text-muted-foreground`. They are separated by `ChevronRight` 14px in `text-muted-foreground`. Never type "›", "/" or "→".
  - The current crumb or title is `text-body`, `--weight-label`, `text-foreground`, one line, `truncate`.
  - Meta goes inline after the title: `text-caption text-muted-foreground`, one line (see the artifact meta below).
- **Right side.**
  - Actions are `Button variant="ghost" size="default|icon"` at `--control-height`, with a gap of 4px.
  - A toggled action (Chat, Tabs) uses `aria-pressed`; pressed means `bg-sidebar-accent text-sidebar-accent-foreground`.
  - One primary (`variant="default"`, blue) at most per header (Share or Publish).
- **The header never uses a size above `text-body`.** The page title (`text-title`) belongs to the content, not to the bar.
- **Under 768px.** `min-height: var(--header-height-touch)` and controls at `--control-height-touch`. The path is hidden; the bar holds the sidebar trigger, Filters and the ⋮ menu.
- **While the workspace loads.** The bar is already the loaded bar: the filters' places are held by `Skeleton` blocks at `--control-height` (the Filters button's on a phone), so nothing moves when they arrive.
- **Second row** (`.detail-header-below`, the editor toolbar). 40px, `border-top: 1px solid var(--border)`. It is rendered only when it has children. An empty row is a bug (the empty strip on the content artifact screen).
- **Persistent shell.** What does not change between two items stays mounted and drawn: the top bar, the second sidebar, a header's actions and the editor's formatting bar. Only what changes (the title, the text) shows its skeleton. The formatting bar's place, while a document or the editor loads and while the agent writes it, is the bar itself with its controls disabled (`EditorToolbarPlaceholder`, `editor-toolbar.tsx`), never a grey block; the editor's own bar replaces it in the same row. Switching files in the Brain or opening a content never takes the bar away.
- **Back.** On a full-page detail, the way back is the breadcrumb, or the `DetailHeader` `ArrowLeft` icon button. No "← All prompts" links and no `.st-back`. An artifact, a content and a skill opened from their list all have the arrow, from the first frame, then their type (`ArtifactIcon`, 20px; a `Skeleton` of its size while an artifact loads), then the title. A Brain file has neither.
- **`DetailHeader` density.**
  - `default`: title plus inline meta.
  - `compact`: the same, but with no leading back button. Used for the chat panel and the side artifact panel.
- **Artifact meta (Drive style).** One caption, never the kind ("Content": the sidebar names it). "Live data" and "public link" are states of the Share button (its icon, `Globe` when the link is on, and its tooltip), never text.
  - Idle: "Edited {when}" / "Última edição {when}" (`editedAt` in `lib/report-date.ts`): under a minute "just now" / "há instantes"; then `Intl.RelativeTimeFormat` long style ("5 minutes ago" / "há 5 minutos", "3 hours ago" / "há 3 horas") up to the end of the calendar day; "yesterday" / "ontem"; then the date, "Oct 28" / "em 28 de out.", with the year when it is another year. It ticks every 30 s while the tab is visible.
  - Typing: "Unsaved changes" / "Alterações não salvas". Saving: "Saving…" / "Salvando…". Just saved: "Changes saved" / "Alterações salvas" for a minute. Failed: "Couldn't save changes" / "Não foi possível salvar as alterações" in `text-destructive`, with the one retry button.
  - The tooltip (a `Hint`; the caption is a button only to reach it by keyboard) holds the full date and who: "Edited by the agent on Nov 2, 2026, 10:07 AM" / "Última edição pelo agente em 2 de nov. de 2026, 10:07". The save's news goes to a live region once; the minute's tick is never read aloud.
  - The title has priority: it keeps its width and is cut only past the whole row. The caption takes what is left, cut with an ellipsis; with less than 8rem left it is hidden (it wraps to a line the header hides), and the title's tooltip still says it (the whole title and the full edited date). A failed save's retry sits first among the actions. Under 768px an artifact's actions take a row under its title.
### The agent's workspace
- **Panes.** Agent > Chat's chat and artifact share the width in a `ResizablePanelGroup`: drag the line or move it with the arrow keys; sizes are kept per device (`useDefaultLayout`). Phones show the chat alone, the artifact in a sheet. There is no conversations column or rail: one sidebar on screen, the app's.
- **The chat bar.** One `DetailHeader` at every width (`.agent-chat-bar`): the navigation toggle (the only one, as the app top bar steps aside on this screen), Conversations / Conversas with its shortcut (`Kbd`, hidden on a phone and on touch), the open conversation's title (renamed in place by a click, `EditableTitle` as an artifact's title; an `h1` reading "New conversation" / "Nova conversa" before it exists and in the demo) and New / Nova (its word hidden under 480px, its name kept).
- **The conversations.** Closed until asked for (a click, a tap, Enter, ⌘K, or the pointer resting on the button: `openOnHover`, which leaves the focus in the message box). **Hover intent** (13/11/2026): `delay={150}` is Base UI's rest time, restarted by every move of the pointer over the button, so it opens only when the pointer rests (or barely moves) there 150ms and never when it just crosses the page; leaving, Base UI's safe path toward the list and `closeDelay={300}` keep it open on the way in, as in assistants that live inside another product (Atlassian Rovo, Linear, Slackbot, Notion, Copilot in Word). From 768px they open in a `Popover` under the button (`.agent-conversations-popover`, 360px, up to 70% of the height); under 768px in a bottom `Sheet` (the catalog's sheet; the unused `Drawer` is not a second way). The same `ConversationList` in both, the demo's too: the search takes the cursor on open (not on touch), the arrows walk from the search through the rows and back, Enter opens a row (or, from the search, its first result), Esc closes and gives the focus back to the button. Rows keep their menu (rename, pin, delete) and their date groups (pinned, today, yesterday, 7 and 30 days, older).
  - **Shortcut ⌘K / Ctrl+K** toggles them on Agent > Chat only (`lib/agent-shortcut.ts`, guard `tests/agent-shortcut.test.mjs`). Nothing else in the app binds it (the sidebar is ⌘B); a browser's Ctrl+K (the address bar's search) gives way to the page, as in GitHub, Slack or Linear. It never fires while the person types in another field (a rename, a search, the artifact's text): only from the message box or outside any field. The button says it with `aria-keyshortcuts`.
  - **One resize line** (`ResizableHandle`, every boundary: chat, artifact, a content's chat and document). At rest a 1px `--border` line with a wider hit area; under the pointer, while dragged and on keyboard focus it turns a 2px `--border-strong` line. Never an outline (an outline around a 1px line draws two bars), never a grip, never blue; after a mouse drag it rests again.
- **Opening.** Agent > Contents and Artifacts, from the sidebar or from another screen, open on the list; an artifact opens only from its link (`?artifact=`) or a click. Everything opens without its chat (the Chat button opens it in Ask Lastfind's panel, below); only a request left to send opens it.
- **Opening an artifact, no shift.** Opened from its link while the workspace loads, the app shows the artifact's page skeleton (`ArtifactPageSkeleton`), never the list frame under the top bar that then steps aside. A member's artifact opens on the text skeleton, then straight in the editor: the editor's code is asked for as the artifact starts loading, it draws its text in its first render (`immediatelyRender`), and the reader is never shown first (the two draw the same text a little apart, and the swap moved it once on screen). Readers get the reader directly. Guard: `tests/artifact-document.test.mjs`.
- **The selected passage** of an artifact floats over the message box's top edge (a queued-message row), out of the flow: attaching or removing it moves nothing in the chat.
- **The agent at work.** While it answers, its message ends with what it does now, after the last words and artifacts; the steps already done stay on top. The message box shows no placeholder meanwhile. The artifact of that chat (beside it, or the page's own) is read-only for the whole answer, its title too.
- **The public demo.** `/demo` shows Agent > Chat only, with example conversations in the real chat (the same rows, steps, artifacts beside, receipts), read-only: no row menu, no rating, no retry, no new-window link. The new-conversation screen offers the examples' questions, which open them. The message box keeps its frame at full contrast but takes no text (`readOnly`, never a greyed `disabled`): its placeholder says the demo is read-only and the agent does not answer there, and "Start for free" / "Começar grátis", a link to `/app?signup` (`SIGNUP_PATH`, the sign-in page on Create account) in the primary blue, takes Send's place (`AgentComposer locked`).
- **Agent states.** One sign for something under way, in words: the live label (`LiveLabel`, catalog `components/ui/live-label.tsx`, entry "Agent states" in `/design-system`). Nothing spins as the chat's main state.
  - **Live label.** The state said in words ("Thinking…" / "Pensando…", "Searching the web…" / "Pesquisando na web…", "Editing the artifact…" / "Editando o artefato…"), shimmering slowly from `--muted-foreground` to `--foreground` (a wide band, a third of the words at full strength, in a 1.6 s sweep every 2.2 s, starting after 0.6 s so a short step never flashes), with a discreet timer (`4 s`, `1 min 05 s`) from the first second. The timer is `aria-hidden`: a live region never reads it every second.
  - **Thinking.** Before the first words, and between steps while no words have come: "Thinking…" with its timer, no icon. "Resuming the answer…" and "Reconnecting…" are live labels too.
  - **Steps.** The tool's icon stays still (section 11). The gerund while it runs ("Searching the web…"), the past once done with how long it took ("Searched the web, 4 s"); every tool has its pair in `TOOL_LABELS` (`lib/agent.ts`, guard `tests/agent-states.test.mjs`). A duration shows only when this tab saw the step from its start; otherwise the past alone, never a guessed time.
  - **Failed step.** Its marker is a small red dot (`TraceErrorMark`, the trace's only `destructive`); its words and the reason stay in the line's grey ("Reading a page: the address did not open."). Nothing else turns red.
  - **Writing.** No extra line: a thin caret in `--activity-mark` fades at the end of the words until the answer ends (after a paragraph, a heading or a list's last item; never after a chart or a table).
  - **Done.** The steps fold into a receipt without icon, "Thought for 12 s" / "Pensou por 12 s" with the chevron that opens them (with failures: ", 1 failed"). An answer this tab did not see from the start says "3 steps" / "3 passos". An answer without steps has no receipt.
  - **Stopped.** The square, still, and "You stopped this answer. Tell me what to do differently." / "Você parou esta resposta. Diga o que fazer diferente."
  - **Artifact banner.** The pencil, still, the live label "Editing the artifact…" with its timer, "Read-only until it finishes." / "Somente leitura até terminar." and Stop.
  - **Conversation list.** A thin 12px spinner (`Spinner variant="activity"`, `--activity-mark`) while that conversation answers; a fixed dot (`LiveDot`) when its answer ended while another was open, until it is opened.
  - **Less motion.** Under `prefers-reduced-motion` the shimmer is still text in the line's colour, the spinner a still arc, the caret still; the timer keeps counting (it is information).
- **Locked while it writes.** The artifact of that chat (beside it, or the page's own) is read-only for the whole answer, its title too. The text stays on screen (`data-locked`, `aria-busy`), never a skeleton or a blank pane; a write reloads it in place and never remounts the pane. Over it, a sticky `Note` banner says it in the chat's own sign (the pencil, still, the live label "Editing the artifact…" / "Editando o artefato…" with its timer, then "Read-only until it finishes." / "Somente leitura até terminar.") with a Stop button that stops the answer. When a write lands, the blocks whose text is new get a `--range-selected` box with a `--primary` edge for 4 seconds (`agent-artifact-changed`, drawn over the document, never inside the editor's DOM); with reduced motion it does not fade. This is the market's shared rule (Google Docs, Notion AI, Cursor, ChatGPT Canvas, Claude artifacts): the content never disappears, a status names what the AI does with a way to stop it, and the change is shown where it landed.
- **A content's tabs.** From 1024px a floating panel, not a sidebar (`SectionSidebar surface="floating"`, `TabsRail floating`): a card (`--popover`, `--border`, `--radius-xl`, `--shadow-md`) over the page's right edge, in view while the text scrolls. The document keeps a gutter for it, open or folded, so opening or folding never moves the text; folded, only its round toggle stays. From 901px the whole pane scrolls (`.agent-artifact-docs`), so its scrollbar sits at the page's right edge. From 901 to 1023px the tabs are the second sidebar (no toggle, nothing moves); up to 900px one menu above the document.
- **AI credits as they go.** The account menu's AI credits (and the chat's limit) follow an answer while it spends: the agent sends the month's use after every model call and when the answer ends, on Agent > Chat and beside an artifact alike; never only on reload.
- **Ask Lastfind** (12/11/2026, after Ahrefs' "Ask Ahrefs"). Every project screen except the Agent's own screens (they are the chat), Admin and the public demo has one button at the bottom right: `Button variant="ink"`, a pill (`999px`, `--shadow-md`, 40px tall) with the Agent's nav icon and "Ask Lastfind" in both languages, a product name like Semantic Branding (only the icon under 640px, its name kept; the panel's other texts are translated). It is a `SheetTrigger`: it says it is open, and hides while the panel is open. It opens Agent > Chat in Ask Lastfind's panel (`AskLastfind` in `AskPanel`, agent-screen.tsx), never a second chat: the same `LiveThread`, message box, conversations (History is the same `ConversationList`, rows open only), model, limits and credits.
  - **One panel, four states** (13/11/2026, `AskPanel`; its state, `lib/ask-panel.ts`, is the tab's and survives the app's navigation and a reload). **Collapsed**: only the button. The button opens it in the last way it was used, **floating** at first: a card at the bottom right (432px wide, up to 640px tall, `--radius-xl`, `--border`, `--shadow-lg`) over the page, which stays usable. **Pinned to the side**: the right sidebar, the whole height and the same 432px: the screen and its fixed top bar narrow for it. **In a new window**: Agent > Chat on the same conversation in its own window (`window.open` named `lastfind-ask`, a tab on a phone); this tab collapses. From 768px the page stays usable beside it (`modal={false}`, `overlay={false}`, `disablePointerDismissal`); on a phone floating is a sheet at the bottom and pinned a full-height sheet, both over a dimmed page. Closed, it keeps its conversation and an answer under way goes on.
  - **Every state reaches the others**, each control an icon of the state it leads to, with its `aria-label` and a tooltip of the same words (`Hint`): **Pin to the side** / "Fixar na lateral" (`PanelRight`, floating) or **Unpin from the side** / "Soltar da lateral" (`PictureInPicture2`, the card in the corner, pinned); **Open in a new window** / "Abrir em nova janela" (`ExternalLink`, the app's one icon for a new window, floating and pinned); **Close** / "Fechar" (`X`, or Esc: back to the button, the focus too). The new window's Agent > Chat bar has **Back to the panel** / "Voltar ao painel" (text, no icon) while the tab that opened it is there: that tab's panel opens again on the conversation, in its last way, and the window closes. Never a sparkle; none of these is a navigation destination, so none comes from `nav-icons.ts`.
  - **Motion**: 180ms, `cubic-bezier(0.2, 0, 0, 1)`, opacity and transform only. Opening and closing, floating rises from the button's corner (`translate` 16px, `scale` 0.96) and the button fades under it; pinned slides from the right edge. Floating and pinned trade places in one view transition (`morphAskPanel`, `view-transition-name: ask-panel`): the page lays out once for its new width, under the snapshot (never an animated width or margin), and the panel glides from its old box to the new one. `prefers-reduced-motion`: no view transition, and globals.css stops the transitions; every state still changes at once.
  - **The same panel on an artifact's page**: its Chat button opens the conversation about the artifact (`ArtifactChat`) in `AskPanel`, floating or pinned at the right of the screen, never as a pane between the app and the text. Its New chat starts a new conversation about it; the new window opens Agent > Chat with the conversation and the artifact beside it.

## 7. Cards and card rows
- **Card.** Always `SectionCard` (`.analytics-panel`): `bg-card`, `1px solid var(--border)`, `rounded-lg` (8px), no shadow.
- **Header.** `SectionHeader`: `px-5 py-4` (20/16), one line, `text-section` title, an optional `InfoHint` icon right after the title, and an optional single `action` on the right.
  - The explanation goes in the `InfoHint`, never in a description line under the title. The one exception is a Settings or Admin form card (`SettingsBlock`), whose `description` says what the form changes; a card that shows data never has one.
  - A "View all" action is `ViewAllAction` (an anchor plus `DrillArrow`). Under 640px it shows only the arrow (its words stay its accessible name, the target 40px wide), so the title keeps its one line on a phone.
- **Body.** `inset="padded"` means `px-5 pb-5`. `inset="none"` is for a full-bleed table or chart.
- **Row harmony** (Overview's `.overview-grid`).
  - Cards on one row stretch to the same height, and every header is `min-height: calc(2rem + var(--control-height))` with or without an action. So both bodies start on the same line.
  - Gap 20px. Columns `minmax(0,1.24fr) minmax(0,1fr)` (Overview) or equal.
  - A list beside a chart shows the whole rows that fit beside it: a table in a `.rows-fit` card takes no height of its own and shows as many rows as fit the height its neighbour gives the row (`useRowsThatFit`, from the rows as drawn, read again when the table or its room changes; at least five, the row growing to them evenly). A row is never cut at the card's foot and rows are never stretched to fill (14/11/2026): what is left, less than a row, stays under the last one. Overview's Brand ranking beside the brand trend (your brand always among them; in one column, six), Query Fan Out beside Top terms, and Most cited domains and pages beside the Site and Content types donuts (in one column, five).
  - The brand trend draws the Brand ranking's brands, in the ranking's order: one set of brands for the row (12/11/2026).
  - Guard: `tests/card-row-harmony.test.mjs`.
- **No internal scroll.** A card, table or list in page content never scrolls inside itself: it shows every row, or a top N with a "View all". Only menus, popovers, dialogs, sheets, the chat, the editor and a list screen's own scroll pane scroll on their own. Guard: `tests/no-inner-scroll.test.mjs` (its allowlist says why each one may).
- **Metrics.** A KPI strip is `MetricGrid` of `MetricCard`: label `text-body` muted with its definition in an `InfoHint`, value `text-metric`, change `Change` (only the figure, such as `+6.6 pp`; no statistics line). `columns` is how many fit on a line (3 by default, 4 for four metrics) and `mobilePairs` puts two per row on a phone; the strip stacks below 900px.
- **Changes.** `Change` (`shared.tsx`) in `--state-good|bad|neutral`, its tooltip naming the compared dates. On a card, a change of less than `MARGIN_OF_ERROR` (5 points, `lib/semantic-perception.ts`) is within the margin of error: neutral, never green or red, a position's change too. The margin is for cards only (10/11/2026): a table colours every difference, its `Change` passing `margin={0}` (Brands, Sources, Prompts, Score ranking), and so does a count. It is gone when comparison is off, and absent when the comparison period has no data (the card's or the column's info says why). A list shows the change beside the figure, without the unit (the column names it).
- **Bars.** `BarList`, the one horizontal bar list (topic coverage, Semantic Branding): one 0 to 100 scale, a figure per row (a missing one says why) and an optional `mark`, a tick at a rival's value named in its balloon. No brand or item position beside a figure ("2nd", "5th of 9"): a ranking says it only in its `#` column.
- **Top terms.** `TopTerms` (`fanout-view.tsx`, Overview's Top terms and Query Fan Out's Common terms): the words and phrases of up to three words the AI searches beyond the prompt, ranked as search tools rank keywords, in a `BarList` (the bar against the most searched, the figure in searches and their share), each term a link to Query Fan Out on it, and under it the listed terms that appear with it in the same searches (`BarList` `detail`, `TagBadge quiet`). Phrases (2 or 3 words) and words are two lists, Phrases first: one ranking would always put the single words on top. Overview (`TopTermsCard`) shows six, the switch in the card's header; Query Fan Out's Common terms has them as tabs, beside Over time.
- **Collapsible rows.** `Accordion variant="rows"`: bordered rows with no fill, the open row's content under a divider (Semantic Branding's justifications). The own brand is told by the "You" `TagBadge`, never by a tint.
- **Tabs.** `Tabs variant="line"` is the app's tab strip (Brands, the Prompts status, Query Fan Out, Semantic Branding): the active tab underlined, wrapping instead of scrolling. A document's parts are a `SectionSidebar`, not tabs.
- **Chart cards.**
  - Always `TrendCard` (trend lines) or `SectionCard` + chart + `ChartLegend`.
  - Legend: `ChartLegend` at the card foot: `text-caption`, 8px dot, gap 8px/16px, padding `12px 20px 16px`.
  - Beside a donut (Site types, Content types) the legend is `ChartLegend layout="list"`: one row per slice, `text-body`, the share at its end in `tabular-nums`, rows of `--nav-row-height` (`--control-height-touch` on touch); with `onSelect` the whole row is the button that opens that type in Sources, an arrow at its end. "Other" and the types past the first six are one slice, "Other types", last; a single leftover type keeps its own name. The donut card sets its row's height with its whole legend, never an inner scroll.
  - Each legend name keeps its whole width and the legend wraps to more lines; a name is cut (ellipsis, full name on hover) only past the card's width or 20rem.
  - A radar is given every brand of the project and draws the first ten (your brand, then by score).
  - When the chart has several series it is `interactive` (toggle buttons, `aria-pressed`).
  - **The legend names only what the chart draws by default.** The brands past the first ten that nobody turned on or off (`folded`, from `useSeriesToggle`) wait behind a final "+N" whose menu (`DropdownMenu`) turns one on; a chart of ten brands never reads as eleven. A brand the person turned off stays in its place, struck out. Guard: `tests/chart-legend-fold.test.mjs`.
  - **At most 10 brands by default, on every brand chart** (trends, the radar, score bars, the agent's charts): `CHART_SERIES_COUNT` (10) in `lib/chart-series.ts`, the one constant. The default view is the own brand plus the biggest totals (`defaultShownSeries`: the brand and nine more); a bar list without a legend shows the best ten with the own brand always among them (`cutBrandRanking`). A project's brand and its 10 monitored competitors are 11 brands, so one always waits behind the legend's "+1".
  - Brand colours come only from `seriesColorVar` (`lib/chart-series.ts`), keyed by the brand's place in the project's competitor list, so a brand has the same colour on the trend, radar, legend and score bars. Twelve distinct colours: the brand and 11 competitors. A 13th brand on gets a shade of a slot toward `--foreground` (darker on light, lighter on dark), never an exact repeat.
  - Every brand chart and ranking links to the brand (`rowLink`, `onSelectSeries`).

## 8. Tables (Brands is the reference)
- **Component.** Always `DataTable` / `DataTableScreen`. Never a raw `ui/table` in screens.
- **Width.** A list screen's table is always the full-bleed pane, the whole width of the screen, with or without metric cards above it (`DataTableScreen cards`: the cards keep the content gutter, the table below runs edge to edge). It never scrolls the page sideways.
- **Phones.** In a phone-wide pane (under 720px) a list screen's table (`fill`, Brands, Sources and the others) stacks as cards, as `singleLine="wide"`: the name column (`mobile: 'title'`) on top in full with the row's actions (`mobile: 'actions'`, the ⋮ menu, 40px) at the end of its line, then the figures two to a row, each label (`label`, else the header's text) above its value, so the name and the key figure are always on screen without scrolling sideways. A small text action given as a value ("Monitor to measure") sits on the values' line. The column headers give way to one bar above the cards: "Sort by" / "Ordenar por", the catalog `SelectField` of the sortable columns, the direction button, and one `InfoHint` with what each column measures. A single-line table that fits its card (`minWidth={0}`: Overview's rankings) stays a table and drops its `mobile: 'hide'` columns (the rank), leaving their room to the name; one that does not fit and has a name column (`mobile: 'title'`: Budget, Competitors, Members, a source's prompts) stacks as cards like a list screen (12/11/2026: sideways it hid its figures and actions past the card's edge). A card shows its name and its `mobile: 'wide'` lines whole, wrapped between words (a one-line cut on a wide table wraps there), never cut mid-word. Score by AI keeps the brand column fixed and shows three AIs to a screen, the rest scrolling in from a column edge.
- **In a card.** A single-line table inside a `SectionCard` (Overview rankings, Products overview) passes `minWidth={0}`: it fits the card and its cells truncate, instead of the 720px floor of a list screen.
- **Toolbar.** `DataTableToolbar`: `padding: 8px 20px` (48px tall with a 32px control, the header's height, and its hairline; `--data-table-toolbar-height`), `border-bottom`, controls at `--control-height`, gap 12px.
  - One line between the toolbar and the column headers, never two (an empty row under the search): the header row drops its top line under a toolbar or note, the phone sort bar between them or not (`overview-presentation.css`).
  - It has a `SearchField` first, filters next, and actions on the right.
  - Explanations go in the toolbar's `InfoHint`, never in a `<p>` or a `Note` above the table.
- **Rows.**
  - `singleLine` on every list table: each row is one line at `--table-row-height` (42px), cells `truncate`.
  - A list whose first column is long text (Responses, the prompt list, AI models, topics, projects) uses `singleLine="wide"`: one line from a tablet-wide pane up, the stacked cards in a phone-wide one, so the phone never opens on a table scrolled past its key column.
  - On screens where a header filter does not apply (Semantic Branding ignores topics, tags and brands), the bar does not show it, rather than showing it disabled.
  - Longer text goes in a `Hint` on the cell, or in a `text-caption` second line only on mobile.
  - A discovery that may be a monitored brand (`sameAs`) shows "Same brand?" (`quiet` `TagBadge`) in place of its "Discovered" status, its balloon naming that brand; the row's menu then opens with "Merge with <brand>?", the usual merge confirmation, undoable. A status badge is never truncated: on that row "Review domain" moves into the menu, and when room still runs out the brand name truncates (its balloon says it whole). On a phone the menu item is enough.
  - No `whitespace-normal` in a column.
- **Width.**
  - The name column uses `shrinkTo` with a floor of `12rem` and a max of `28rem`.
  - No other column is wider than `20rem`, and a table has at most 6 data columns plus actions.
  - In a table with a name column (`shrinkTo`), a column without a width of its own that sorts as text (Query Fan Out's Topic and Intent) is a text column: at least `10rem`, so a short label keeps one or two lines, cut with an ellipsis past two, and it shares what the name column leaves. The other columns without a width (figures, rates, icons) then take just their header and value, never the spare width (14/11/2026, `widthOf` in `DataTable`).
- **Cells.**
  - Cells are `--weight-text`. No bold, except the summary row.
  - Headers are `--weight-label`, `white-space: nowrap`, on `bg-card`.
  - The header row is as tall as a body row, `--table-row-height`, on every table (Semantic Branding's heatmap too); a row grows only when a cell wraps.
  - Every cell reads at `text-body`: a `TagBadge`, a `code`, a `text-caption` second line inside a cell take the row's size (one rule in `overview-presentation.css`). A column shows every value with the same component: Agent > Contents' Access is a `TagBadge` for "Workspace" and "Public link" alike.
  - Hairlines go between columns and below rows, and the last row has none. A file list (Agent > Artifacts and Contents) uses `lines="rows"`: the lines below rows only, no column lines, as Google Drive.
- **Editable cells** (12/11/2026, the New project wizard's tables). A value edited in a table is the cell itself, never a field box inside it: `Textarea variant="cell"` for every value of a table that stacks on phones (a name, a definition, a prompt; a one-line value takes `rows={1}` and refuses Enter), `Input variant="cell"` only for a short value in a table that never stacks. The field fills its cell with the cell's padding (13/11/2026, `data-table.css`): a click anywhere in the cell edits it, and the whole cell takes the `--muted` fill when hovered or edited (selection by fill, never a ring), never a box inside it; in a phone's stacked card the field takes the fill, under the card's label. At rest the value keeps one line, its end faded when it runs past the cell (a textarea draws no ellipsis), so a row never wraps at rest; edited, it wraps whole, never cut mid-word, and the row grows to it in 150ms (none under reduced motion); it shrinks back 250ms after the edit ends, so a click on a button below (Next) lands before the row moves it. An icon before the value (a competitor's favicon) sits in a `label` that is the cell. An invalid value keeps the `destructive` edge. One pattern for every editable list: a `SectionCard` whose header holds the actions (Suggest, Add), the selection column first (`width: 44`, `pl-4`, as Prompts), the remove button last; while its first rows are on their way the table is `DataTable loading`. Catalog: Editable cells in `/design-system`. A list in one cell or field (a competitor's domains, the main one first; aliases) is `TagInput` (13/11/2026): each value a neutral badge with its remove button, a comma or Enter adds (a space too for domains), a pasted list adds every value, Backspace on the empty field removes the last; `variant="cell"` in a table. Never a comma-separated text. Catalog: Tag input in `/design-system`.
- **Columns.**
  - Numbers are right-aligned and `tabular-nums`.
  - Dates use the short format of the app locale.
  - The actions column comes last (switch, then the ⋮ menu, `icon-xs`).
- **Defaults.** `defaultSort`: updated or created descending for lists, score descending for rankings.
- **Badges.** In Overview's most cited lists the name keeps its room: in a narrow card the type badge is dropped whole first; "You" / "Você" is never dropped.
- **Badges.** Only `TagBadge` (tones from the `badgeVariants` `tone` variant). A tone's text is the tone mixed toward `--badge-ink` (black in light, white in dark), so "You" and "Monitored" pass AA in both themes.
- **Entities.** A brand is shown with `BrandName` (favicon plus name). A listed URL is `UrlCell`: the click opens its page in the app, labelled by the page title when known (else the URL, the URL in the tooltip), and the icon beside it opens the original in a new tab; never a loose `<a target="_blank">`.
- **A name drawn as a text button** (Settings > Projects opens the project from it) starts its text where the column's text starts, on the table and on a phone's card (`data-table.css`, one rule for every table).
- **Cells hold no blue links.** `rowLink` makes the whole row the link (hand, hover, Enter, Ctrl/⌘-click for a tab). A navigable card is one `DrillLink` around its whole content (`buttonVariants` ghost), with nothing interactive inside it.

## 9. States and skeletons
- **Loading.**
  - Every data component takes `loading` and draws its own skeleton inside its real frame: the same card, header, toolbar, columns, legend and row height. This applies to `SectionCard`, `TrendCard`, `DataTable`/`DataTableScreen`, `MetricGrid`, `DetailBody`, `SectionSidebar` and `ChartLegend`.
  - A screen skeleton is the screen rendered with `loading`.
  - `live-app.tsx`'s workspace skeleton maps each tab to that screen's exported `<Screen>Skeleton` (`screenSkeletons`), under the screen's real `PageHeading` (the same element the loaded screen renders). No generic skeleton exists. The analytics ones: `OverviewSkeleton` (`overview-kpis.tsx`), `TopicsSkeleton` (`overview-topics.tsx`), `BrandsSkeleton` (`brands-screen.tsx`), `BrandPageSkeleton` (`brand-page.tsx`), `ProductsSkeleton({ view })` (`products-view.tsx`), `ProductPageSkeleton` (`product-page.tsx`), `SemanticSkeleton` (`semantic-summary.tsx`), `ComparisonSkeleton({ view })` (`comparison-view.tsx`), `SourceEntitySkeleton` (`source-entity-page.tsx`), `FanoutSkeleton` (`fanout-view.tsx`), `OpportunitiesSkeleton` (`opportunities-view.tsx`), `SettingsSkeleton` and `AdminSkeleton` (`settings-block.tsx`).
  - The shell's own parts load the same way: the top bar's filters, the project switcher and the account row (sections 4 and 5).
  - Skeleton blocks: text lines are `Skeleton inline h-lh`, charts `h-64` inside the card, and table rows `--table-row-height`.
  - The full-page loading indicator is the Lastfind telescope (the header's PNG) moved by a CSS transform, with its status text; under reduced motion only the text stays.
- **Empty, error, unavailable and in progress.** Always `EmptyState` (built on `ui/empty`):
  - `frame="card|bare|inline"` and `tone="empty|error|progress"`.
  - Title `text-body` `--weight-label`, description `text-body text-muted-foreground`, 16px icon.
  - `onRetry` draws the one retry button, "Try again" / "Tentar novamente". A toast's or a strip's retry action uses the same words (`RETRY_LABEL` in `shared.tsx`).
  - Filters that leave nothing to show say so and offer to clear them ("No responses match these filters" with a Clear filters action), never "No responses in this period".
  - When the workspace itself cannot load, the screen is an `EmptyState tone="error"` with `onRetry`; the sidebar offers no action that needs the workspace (no New project).
  - A page that fails to load (the database busy for an instant, a deploy rolling out) tries again by itself once after 2 seconds, at most once a minute (`app/error.tsx`); a failure that stays shows the error page. An error never names a provider or its status (principle 7).
  - An error always has `CircleAlert` (a failed step of the agent's trace has its red dot instead, section 4).
- **Disabled.** `opacity-50`, `pointer-events-none`, the reason in a `Hint`.

## 10. Focus and selection
One rule set, in `globals.css` `@layer base`:
```css
:focus-visible { outline: 2px solid var(--ring); outline-offset: 2px; }
:is([data-sidebar=menu-button],[data-sidebar=menu-sub-button],[data-slot=tabs-trigger],
    [data-slot=dropdown-menu-item],[data-slot=select-item],tr[data-clickable],.table-sort):focus-visible
  { outline-offset: -2px; border-radius: var(--radius-md); }
:focus:not(:focus-visible) { outline: none; box-shadow: none; }
[data-input='pointer'] :focus-visible { outline: none; }
```
- **A click never leaves a ring.** Chrome also matches `:focus-visible` on a clicked button as soon as any key is pressed, even Shift alone, ⌘C or ⌘Tab back to the window: the ring then "sometimes" showed after a click. `ApplicationStyles` (`components/application-styles.tsx`, mounted by the root layout of both editions) keeps the last input on `<html data-input>`: `pointer` on any pointer press, `keyboard` on a key that moves the focus (Tab, the arrows, Home, End, Page Up, Page Down; never a modifier, Enter, Space or Esc). While it is `pointer` no outline shows. Guard: `tests/focus.test.mjs`.
- **No other focus rule anywhere.** No `focus-visible:ring-*`, `focus-within:ring-*` or `has-[:focus-visible]:ring-*` in any component (inputs and textareas included: they show focus as their border), no `:focus-visible` in component CSS.
- **Cursor.** One rule in `globals.css`: every control (button, link, menu item, option, tab, switch) shows the hand, disabled ones `not-allowed`. No catalog item sets `cursor-default` (only the select's scroll arrows). Adjacent nav rows leave no dead strip: each row's hit area reaches half the gap to the next (a `::before` on the link, over its row), so the pointer going down a sidebar never flashes the arrow between two links. A balloon never sits under the pointer (`disableHoverablePopup`). Guard: `tests/shell-pointer.test.mjs`.
- **Inputs and input groups.** They show focus as `border-ring`.
- **Inside the sidebar.** The outline colour is `--sidebar-ring`.
- **Selection.**
  - A selected row, block, card or item is shown with `bg-sidebar-accent` (nav) or `bg-[var(--table-hover)]` (content blocks), never a ring or border.
  - After a menu closes, focus returns to its trigger with no visible ring for mouse users. This is covered by `:focus:not(:focus-visible)`.

## 11. Colour, CTA, radius, icons
- **Colour.** Semantic tokens only: `background`, `foreground`, `muted-foreground`, `primary`, `border`, `ring`, `destructive`, `warning`, `chart-1…12`, `sidebar-*`, `--state-good|bad|neutral`. Blue (`--primary`) is for actions and links, never for running text or the active nav row's text.
- **Source and content types.** One fixed hue per type (`--source-type-*`, read through `SOURCE_TYPE_COLORS`), always next to its name: colour never carries the meaning alone. Not classified is a dashed neutral chip with its reason, never `0%`. A legend row opens Sources filtered by that type.
- **Links.** No underline at rest, underline on hover; links in the running text of answers, docs, articles and legal pages are always underlined. Anchors drawn as buttons and menu items never underline. One rule for the app and the site, `components/lastfind/link-hover.css` (guard `tests/app-typography.test.mjs`).
- **Tooltips.** Every balloon opens where the pointer is, its arrow on it, and follows it across the element; from the keyboard it sits on the element. The exception is a collapsed sidebar's names, which open beside the icon (section 5). Set once: `Tooltip` in `ui/tooltip.tsx` (`trackCursorAxis="both"`, so `Hint` and the collapsed sidebar's names follow) and `ChartTooltip` in `ui/chart.tsx` (every Recharts chart: the balloon centred above the pointer, an arrow under it, slid back inside the chart and the screen near an edge, never wider than the room left there, each row cutting its name before its figure, `.chart-tooltip-anchor` in `globals.css`). A new balloon uses one of the two. On a touch screen a chart's balloon (`ChartTooltip`, the Site and Content types donut, the Semantic Branding radar) closes on a tap anywhere outside the chart, on a scroll, and on a second tap on the same point; a mouse keeps the hover. A tap on a trend shows the day's balloon and never opens that day's answers (the mouse's click does). One hook does it, `useTouchDismiss` (`lib/use-touch-dismiss.ts`): a new chart balloon uses it (12/11/2026: a phone never moves the hover off a chart on a tap elsewhere). Browser test: `tooling/qa-pr/chart-touch-flow.mjs`.
- **CTA.**
  - The primary action is `Button variant="default"`: `bg-primary text-primary-foreground`, hover `bg-primary-hover` with `shadow-[var(--action-glow)]`. It is the same blue as the site's `.btn-primary`.
  - The chat's send and stop are `Button variant="ink"` (black on the light canvas, white on the dark one: `--foreground` on `--background`); Share stays `default`. The person's own message is the `muted` bubble (light gray, `--muted`).
  - Inside the chat (12/11/2026) the app's hierarchy holds: the message box's actions are ink (send, stop, and Send when a question is edited); the choice beside a primary is `outline` (Cancel, Skip, Decline); a card's or popover's main action is `default` (Approve, the feedback's Send); the bars' actions are `ghost` text (New, History, Conversations); a message's or row's actions are `ghost` icons with their `aria-label` (copy, ask again, edit, remove). Guard: `tests/agent-ui.test.mjs`.
  - One primary per view region (header, dialog footer, composer).
  - Secondary is `outline`, tertiary is `ghost`, delete is `destructive`.
  - An action button with text has no icon, only the text: "Adicionar prompt", never "+ Adicionar prompt". It holds for every variant, dialog footers and empty states included; a busy one shows the `pending` spinner. Outside the rule: icon-only buttons (`size="icon…"`, with their `aria-label`), navigation icons (`nav-icons.ts`), the chat's send and stop, menu items, chips, toggles and filters (`aria-pressed`, `aria-expanded`), the triggers that open a menu, popover or section (their chevron), and `ViewAllAction`'s arrow. Guard `tests/cta-no-icon.test.mjs`; catalog `/design-system#button-cta`.
- **Radius.**
  - `rounded-lg` (8px) for cards, panels, menus, popovers and dialogs.
  - `rounded-md` (6px) for buttons, inputs, nav rows and menu items.
  - `rounded-full` only for avatars, dots, the composer's send and stop, the folded tabs button and the Ask Lastfind button.
  - No other value.
- **Icons.**
  - lucide only, `aria-hidden` when next to text. 16px in content, controls and menus; 20px in the main sidebar; 14px for breadcrumb chevrons and inline `DrillArrow`.
  - An icon-only button has an `aria-label`.
  - Navigation icons come from `nav-icons.ts`, one per destination (guard `packages/core/tests/nav-icons.test.ts`).
  - No sparkles, emoji, or typed arrows ("→", "›"). One exception: the trophy 🏆 (`LeaderMark`, `semantic-association-report.tsx`) marks the leader of a column, the highest mean of each attribute in Semantic Branding's heatmap and the highest score of each AI in Score by AI, with its words for a screen reader.
  - The agent at work has no animated mark: its states are words (section 4, "Agent states"). Lastfind's lens is not a status.
  - The trace's step icons are lucide at a 1.5 stroke, chosen for the sky: `Telescope` reads the project's data, `Radar` searches, `Earth` reads a page, `PenLine` writes, `SquarePen` changes, `NotebookPen` remembers, `BookOpen` uses a skill. The icons never move. A failed step has a red dot as its marker (`TraceErrorMark`) and keeps the trace's grey for its label and what happened. A folded run's steps are a size smaller (`text-caption`).
  - An artifact's type is `ArtifactIcon` (`components/lastfind/presentation/artifact-icon.tsx`): a document in the system's style, its type colour (`--artifact-*`) and a white glyph, 16px in a list row, 20px in a card or a header. Every skill has the same one (`kind="skill"`, teal, a bolt), never a lucide icon per skill.
